## 3.1 修复：点击「诊断信息」崩溃（2026-10-21 用户报）

**根因**：折叠区的 `onToggle` 写成 `setCollapsed((prev) => ({ ...prev, advanced: event.currentTarget.open === true }))`。
状态更新函数是**稍后**执行的，而 React 在事件派发结束后把 `currentTarget` 置空 ⇒ updater 里读到 `null.open`，
抛 `TypeError: Cannot read properties of null (reading 'open')`，面板整块崩。修复：先 `const open = event.currentTarget.open === true`，
再把 `open` 放进 updater；「最近目录」折叠同一处坑一并修。顺带给诊断块的 `daemon.pid` 加了未知保护。

**回归**：probe-layout 新增 7 条断言（诊断/最近目录在"currentTarget 被置空后"执行 updater 不崩且写入 open；
`daemon: null` 时诊断块不崩），现 **17/17 PASS**。

## 3.2 对齐 VS Code Remote Explorer 的 WSL TARGETS（2026-10-21 追加）

用户指出「没有参考 vscode-wsl 的交互」。此前只做了头部下拉，形状不像 VS Code；现改为：

- 多发行版时在主体顶部渲染 **「WSL 目标」列表**：每行 = 状态点 + 发行版名 + 「默认」/「当前」徽标 + 运行/未运行；
  点行即切换目标（`onDistroChange`），当前行 aria-current=true；
- 单发行版不渲染该区块（避免只有一个选项的死控件）；
- 头部下拉删除（同一动作不再出现在两处），头部只保留「标题 + 目标路径 + 守护药丸 + 动作」。

对应 VS Code 的差距仍然存在且未伪装：VS Code 还有**状态栏远程指示器**（点击弹命令）、**命令面板**入口、

我们目前只有「切换目标 + 浏览 + 添加为工作区 / 开会话 / 守护动作」。

**2026-10-21 补充（用户批准的两件）**：目标行内加入「设为默认 / 停止」两个动作（停止走二次确认，`runDaemon` 支持带 `distro`）；底栏加入 `WSL: 发行版` chip（原生 details，点开 = 启动守护 / 停止守护 / 设为默认）。
