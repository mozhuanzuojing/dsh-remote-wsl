# 面板 UI 重做（2026-10-21）—— 结构、交互与证据

## 1. 目标

用户：「UI 重做，要最好的交互」。上一版的问题（来自截图与代码对账）：

1. **看不见重点**：头部只有标题 + 一行"目标 X · 路径" + 一个「未物化」徽标；守护状态只在底栏，且"启动守护"按钮和药丸式入口重复。
2. **空间浪费**：卡片里"浏览目录"标题、常去位置、面包屑、路径、筛选各占一行；列表只占内容高度 —— 72 项只显示 6 行，下面一大片空白。
3. **动作分散**：启动守护在底栏、刷新在头部、隐藏文件在卡片头，同一类动作三处。

交互要点：

- **守护药丸**：状态点 + 文字，未运行时**点击即启动**（一次点击，不用先找按钮）；运行中只显示状态（标题里带 slot / pid），破坏性动作仍只在 ⋯ 菜单 + 二次确认里。
- **三层收成两层**：位置条（横向滚动，不换行）+ 导航行（上一级 + 面包屑）+ 输入行（路径框 + 筛选同排）。
- **列表吃满高度**：body 不再整页滚动，滚动体是列表本身（scrollbar-gutter: stable 防抖动）。
- **去重**：删除卡片里的"浏览目录"标题、删除底栏重复的「启动守护」、删除头部「未物化」徽标（会话未物化已经在底部"会话 0"与动作结果里表达）。
- **可访问性**：药丸/开关/上一级全部是原生 button，aria-pressed / aria-label / title 齐全；列表保留 roving tabindex 与 aria-setsize/posinset。

## 4. 未验证 / 限制（如实写）

- **没有真实浏览器的像素/键盘验收**：本机无法在会话内起隔离浏览器跑面板；探针只证明结构、类名、可访问属性与回调接线。
- 需要**重启 DSH** 才能加载新 host/client（client chunk 的 rev 已 bump）。
- 窄态（<420px）没有重做；位置条在极窄时只保证不换行（横向滚动），按钮文字仍可能被挤压 —— 下一轮按 320/360 两档实测。
- 行内动作仍是"进入 / 复制"两个文字按钮，尚未做右键菜单与"在此开会话"的每行入口（需要额外的 action surface 设计）。
