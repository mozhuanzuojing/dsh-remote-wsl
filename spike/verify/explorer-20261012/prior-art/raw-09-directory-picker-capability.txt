== RAW: 官方「目录浏览」能力在本机 web 组合下**不可用**（实测）

RUN4（`dsh --profile t11 --port 8911 --no-open`，DSH_HOME 隔离；web 组合 = `dsh-web-app`）
在页面里直接调官方 client 服务：

  await ctx.get('uiWorkspace').listDirectory(undefined)
    -> DirectoryBrowseError
       "directory browse failed: directory-picker/unavailable:
        directoryPicker.list needs the browse capability; the composed picker serves \"native\""

  await ctx.get('uiWorkspace').listDirectory('C:\\Users\\l')
    -> 同上

  await ctx.get('uiWorkspace').listDirectory('\\\\wsl.localhost\\debian-u8-1\\home\\g')
    -> 同上（与路径无关，是能力缺失）

  ctx.remote.directoryPicker.pick()
    -> Error: cannot get property "remote" without inject
       （该 bundle 的 `exports.inject` 只声明了 ['slots']；要用 `ctx.remote` 必须把它加进 inject）

== 为什么（读代码，可核）==
- `dsh-web-app/cordis.patch.yml:113-114` 挂的是 `@deepseek-ai/dsh-host-directory-picker-auto`。
- `dsh-host-directory-picker-auto/lib/index.js` 的 resolve 规则（文件头 JSDoc）：
  `native` 需要「loopback-only bind + 非 SSH 启动 + 可服务的显示会话（darwin/win32 直接假定成立）」，
  否则退回 `browse`。本机 = win32 + 127.0.0.1 + 非 SSH ⇒ **解析为 native**。
- `dsh-api-workspace-controller/lib/index.js:483/498/517`：
  `pick()` 要 `requireCapability('native','pick')`；
  `list()` 与 `createDirectory()` 要 `requireCapability('browse', ...)`。
  ⇒ 组合只提供一个后端时，另一侧的三个方法必然 `directory-picker/unavailable`。

== 含义（对采纳清单）==
- A3「复用官方浏览能力」在这台机器的 `dsh web` 组合下**做不到**：`listDirectory`/`createDirectory` 全挂。
  （若换成 `browse` 组合/远程浏览器组合，同一个 API 就是可用的 —— 即它是**组合依赖**，不是恒真。）
- A1「加为 WSL 工作区」若要**自己选路径**，不能依赖官方 browse；要么复用操作系统的 native `pick()`
  （但 native `pick()` 会弹**可见**的文件夹选择框），要么走我们自己的树 + `workspaceRegistry.create()`
  （host 侧直连，已实测可用，见 raw-02）。
- `workspaceRegistry.create()` 本身**不走** picker 能力（`dsh-workspace` 直接 `fs.realpath`），
  所以「面板里选好路径 -> 创建 WSL 工作区」这条路可行，且不需要 browse 能力。
