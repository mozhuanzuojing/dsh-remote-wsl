== RAW: 手写 loader bundle 的 `require` 表 + `ctx` 服务面（实测）

被测实例：`dsh --profile t11 --port 8911 --no-open`（DSH_HOME 隔离，见 raw-08）。
方法：三个手写 bundle（`dsh-t11-client-im` / `-lz` / `-plain`）在 **factory 内**逐个
`try { require(spec) } catch` 取样，并把结果同时
(a) POST 到 host 的 `/t11/client-report`、(b) 暴露为 `window.__T11__[role]()`。

三个 bundle 的差别只有 `dsh.client` 声明：
  im    : inject=[7 个官方包] + immediately:true
  lz    : inject=[同样 7 个]   （无 immediately）
  plain : 只有 platform:'web'  （无 inject、无 immediately）

失败（1 项，三个 role 同样失败）：
  @deepseek-ai/dsh-client-runtime
    -> client-modules: require("@deepseek-ai/dsh-client-runtime") missed the module table — not a
       platform seed word, not a materialized module, and no registered package factory
       (a build-time externals drift, or a dynamic dependency that did not arrive)

补充（读代码）：`dsh-client-modules/lib/client.js:698-706` 的 **同步** require 只有三条命中路径
（platform seed / loadCache / factories），否则抛上面这条；`:707-713` 的 `require.async(spec)` 才会
异步抵达 graph row。`:644-661` 的 `arriveGraphRow` 会先按 `row.inject` 抵达依赖再 `arrive(row)`。
