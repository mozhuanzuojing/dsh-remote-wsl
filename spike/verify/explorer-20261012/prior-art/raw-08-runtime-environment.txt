== RAW: 本轮实测的运行环境（可复跑）

## 为什么要自己解包
`C:\Users\l\node_modules\@deepseek-ai\*` 在本轮开始时已不存在（task-1 那次误装进共享目录的
`@deepseek-ai` 子树已被清理），也没有任何已安装的 dsh CLI。按本轮纪律
「不许 npm/pnpm install 到共享目录」，改为**从 app.asar 只读解包到自己的 %TEMP%**。

```
# 解包（自写脚本，只读 asar，只写 %TEMP%）
node %TEMP%\rwsl-client-probe\asar-extract.js ^
  "C:\Users\l\AppData\Local\Programs\DeepSeek Harness\resources\app.asar" ^
  "dsh/" "%TEMP%\rwsl-t11\runtime"
# -> extracted 12412 files

node %TEMP%\rwsl-t11\runtime\dsh\node_modules\@deepseek-ai\dsh\lib\bin.js --version
# -> 0.2.0-rc.2
```

## 隔离的 DSH_HOME + profile
```
set DSH_HOME=%TEMP%\rwsl-t11\home
node <bin> --profile t11 --from-default-profile web --dump-default-config
# profile: %TEMP%\rwsl-t11\home\profiles\t11
# bundles: @deepseek-ai/dsh-base, @deepseek-ai/dsh-web-app,
#          dsh-t11-host, dsh-t11-client-im, dsh-t11-client-lz, dsh-t11-client-plain
# node_modules\: 四个 junction 指向 %TEMP%\rwsl-t11\plug-*
```
用隔离 DSH_HOME 的理由：工作区实验会**真的写** workspace 注册表；隔离后不污染用户的
`C:\Users\l\.dsh\storages`。

## 启动（隐藏、无窗口）
```
set DSH_HOME=%TEMP%\rwsl-t11\home
set T11_PRIORITY=<10 | -10 | 0>
set T11_OUT=%TEMP%\rwsl-t11\results-workspace*.json
node <bin> --profile t11 --port 8911 --no-open        # 后台作业，无 Start-Process，无可见窗口
# -> dsh web: http://127.0.0.1:8911/?token=...
```
- 口令/浏览器页：用会话自带的 DevTools 浏览器打开 `?token=` URL（同 task-1）。
- 未触碰用户宿主（19387）；未用 8911 以外端口；每次结束都停掉自己的 node 进程并确认 8911 已释放。

## 三次运行
| RUN | T11_PRIORITY | bundles 含 im? | 用途 |
|---|---|---|---|
| 1 | +10 | 是 | directoryFlow：+10 输给官方 0；client require 表；workspace 实验 |
| 2 | −10 | 是 | directoryFlow：−10 赢；workspace 实验（修正版，含 id / mkdir 对照） |
| 3 | 0（无人注册该槽） | **否** | 对照：确认 RUN2 的 DOM 元素来自我们；immediately 对照 |
