# DSH 0.2.2-rc.1 适配记录（插件 0.3.20）

- **日期**：2026-11-05
- **基线**：DSH Desktop **0.2.2-rc.1**（`resources/runtime/primary-runtime/runtime.json`）
- **插件**：`dsh-remote-wsl` 0.3.19 → **0.3.20**
- **结论**：WSL preset 在 0.2.2 上由 **broken（UI 不可选）** 恢复为 **已注册**；单测 250 通过 / 0 失败；隔离宿主启动日志复验通过；0.2.2 新增的 `fs.patchText`/`deleteFile`/`moveFile` 已补齐（守护协议 v4）；WSL 侧 `@deepseek-ai/dsh@0.2.2-rc.1` 已预热并写 pin。

## 1. 症状与根因

升级到 0.2.2 后，`~/.dsh/remote-wsl/startup.log` 记录：

```
WSL preset 注册但有 broken（id=wsl，plugins=19）：
tool-subagent-list-agents (@deepseek-ai/dsh-tool-subagent-control/list-agents): never started
```

`never started` 是 preset 注册器 `auditRows()` 对 **import 失败（fiber 未建立）** 的措辞
（`dsh-agent-preset-registry/lib/index.js` 的 `auditRows`）。逐包核对 0.2.2 的 `app.asar`：

- `@deepseek-ai/dsh-tool-subagent-control@0.2.2-rc.1` 的 `package.json` **exports 只剩 `.`**，
  0.2.1 的 `./list-agents` 子路径被删除；
- 该包 `lib/index.js` 里 `list_agents`、`send_message`、`interrupt_agent` 已合并到主入口。

因此只要 WSL preset 继续声明 `.../list-agents` 这一行，整份 preset 就会被判 broken，即使其余
行都健康。

## 2. 0.2.2 标准 preset 的实际变化（对照 `dsh-web-app/presets/*.patch.yml`）

| 变化 | 0.2.1-rc.3 | 0.2.2-rc.1 | 对本插件的影响 |
|---|---|---|---|
| list_agents 归属 | `dsh-tool-subagent-control/list-agents` 子路径 | 并入 `dsh-tool-subagent-control` 主包 | **致命**：保留旧行 ⇒ 整份 preset broken |
| 子模型选择配置 | `modelSelectionSettings: true` | `modelSelection: true` + `modelDiscovery: true` | 旧键在 0.2.2 被忽略 ⇒ 静默丢功能 |
| apply_patch | 无此配置 | `tool-fs` 显式 `applyPatch: false` | 标准模式默认不带 apply_patch；本插件跟随。WSL provider 已实现其依赖的 `patchText`/`deleteFile`/`moveFile`（§3.2） |
| 编辑语义 | CRLF 规范化 + 原行尾写回 | 同 | 本插件 fs-rpc 旧实现未规范化（0.2.1 起就有的差异），本次一并修正 |
| PTC 模式 | `dsh-agent-tool-presentation`（mode: ptc） | `dsh-tool-executor-ptc` | 变体从宿主 preset 文本复制，自动跟随 |

plan-mode 的 `section` 文本在 0.2.1-rc.3 已改成「decision-complete」长版本；本仓库的静态拷贝停留在
2026-10-23 的短版本，本次一并逐字对齐（0.2.2 的 `dsh-plan-mode` 还会校验 section 非空）。

## 3. 改动

### 3.1 preset / 版本声明

- `src/preset.ts`
  - 删除 `tool-subagent-list-agents` 行（`dsh-tool-subagent-control` 主包已含 `list_agents`）。
  - `tool-subagent`：`modelSelectionSettings` → `modelSelection: true, modelDiscovery: true`。
  - `tool-fs`：显式 `config: { applyPatch: false }`（跟随标准模式默认；provider 已有完整实现）。
  - plan-mode `section`：与 0.2.2 标准 preset 逐字一致。**这是主动对齐**：旧短文本在 0.2.1-rc.3
    已经过期（不是 0.2.2 健康性所必需），但本 preset 的定位就是 standard 的静态拷贝，保留过期文本
    会让行为悄悄偏离标准模式。
- `package.json`：0.3.19 → 0.3.20；`dsh.compatibility.dshReleases` 增加 `0.2.2-rc.1: compatible`。
- `README.md`：版本/基线/兼容性/更新日志/协议版本（v3 → v4）同步。

### 3.2 文件系统接口补齐（0.2.2 新接口）

0.2.2 的 `dsh-fs-local` 新增了 `patchText` / `deleteFile` / `moveFile`，`dsh-tool-fs` 的
`apply_patch` 的 update/delete/move 操作直接调用它们。原实现只在设计上支持 write/edit，如果
profile 打开 `applyPatch: true`，WSL preset / UNC 会话会在运行期撞到缺方法。本次从根上补齐：

- `src/fs-rpc.ts`（WSL 守护侧）：
  - 新增 `patchTextOp` / `deleteFileOp` / `moveFileOp`，与 fs-local 同语义（路径锁、版本 CAS、
    `FS_SAME_TARGET`、源删除失败如实回 `sourceDeleted:false`）。
  - 新增纯文本 hunk 应用（`applyHunks`，与 `dsh-fs-patch.applyHunks` 行为对齐，独立实现）。
  - 编辑/补丁改为 `readForEdit()`：CRLF → LF 匹配、写回恢复原行尾；错误码对齐
    `FS_EDIT_NOT_FOUND` / `FS_AMBIGUOUS_EDIT` / `FS_NOT_TEXT` / `FS_PATCH_MISMATCH`。
  - `writeTextLocked` 支持 move 时保留源文件 mode。
- `src/fs-provider.ts`（宿主侧 WSL fs provider）：实现 `patchText` / `deleteFile` / `moveFile`，
  并把 `~` / `~/x` 展开到 **WSL home**（0.2.2 `resolve/lstat` 的新语义）。
- `src/fs-unc-bridge.ts`：普通 UNC 与 `/mnt` 的 `patchText` / `deleteFile` / `moveFile` 全部接到
  WSL fs-rpc，expected 版本按宿主/ WSL 令牌转换（`apply_patch` 不再受 9P DACL 限制）。
- `src/plugin-version.ts`：守护协议 3 → **4**（三个新 op，加法；旧守护 soft 提示 restart）。
- 新增回归：`test/fs-rpc-edit-patch.test.ts`（7）、`test/fs-provider-022.test.ts`（4）、
  `test/fs-unc-bridge-022.test.ts`（4）。

不改动：`engines.dsh` 仍为 `>=0.2.0-rc.2`（0.2.2 满足）；不因为本次适配放弃老版本的加载能力。
老版本上 `modelSelection`/`modelDiscovery` 会被 schemastery 作为未知键合并但忽略、`list_agents`
不再由独立子路径提供——**这是能力差异，不是加载失败**；需要旧行为的用户应停留在 0.3.19。
老守护（协议 < 4）仍可读写/edit，只是三个新 fs op 在 `wsl_daemon action=restart` 前不可用。

## 5. 未验证 / 剩余风险

- **桌面 GUI 尚未重启**：当前宿主进程仍加载旧代码（启动日志停在 01:50 的 broken 记录）。重启 DSH 后
  才会加载 0.3.20，启动日志应变成「WSL preset 已注册」。
- **面板视觉未人工验收**：只验证到 bundle 被 0.2.2 模块加载器纳入清单并 200 可取；布局/交互需在
  浏览器里点一遍（README「面板」节）。
- **SDK 协议**：0.2.2 的 `dsh-sdk-protocol` 仅增强 transport 失败语义，方法名
  `initialize` / `session/prompt` / `shutdown` 与通知 `session.event` / `session.status` 未变；
  `--profile sdk` 仍可用（`dsh --profile sdk --help` 实测）。`wsl_agent` 全链路未用真模型跑一轮。
- **新 fs 接口未跑完整 apply_patch 工具链**：`patchText`/`deleteFile`/`moveFile` 的守护实现用真实文件
  在本地 node:fs 上覆盖了 9 条用例（含 CRLF、context/EOF/空白匹配、10MiB 边界、版本冲突、同目标、
  移动+改写），`daemon-integration` 有真实守护进程 + TCP RPC 的完整 fs op 链，§4.5 另有**真 WSL
  守护**上的同样验证；但「模型 → `apply_patch` 工具 → WSL 守护」这一层未用真模型跑。默认
  `applyPatch:false` 时模型看不到 apply_patch，只有 profile 显式打开才会触发。
- **老版本兼容**：见 §3 末尾，属能力差异而非加载失败。
