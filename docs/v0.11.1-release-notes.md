## 修复

### 守护自动启动后目录浏览不自动恢复（主因）
打开面板时若远端守护未运行，ext4 目录（如 `/home/g`）列目录会先失败；C 逻辑随后自动拉起守护，但**之前失败的目录不会自动重试** —— 界面停在「列目录失败 / 共0项 + 启动守护」，而顶部却显示「守护运行中」，自相矛盾。
现在：监听守护「未运行 → 运行」过渡，若当前目录浏览处于失败态，**自动重跑 `listDir`**，目录自动恢复（手动启动守护也顺带受益）。

### 提示文案订正
- `browser.daemonDownHint` 原文「面板不会为浏览自动拉起守护」与 C 自动启动冲突，改为：「ext4 目录由 WSL 守护读取，需要守护运行。面板会自动尝试启动守护并在成功后自动重试；也可手动启动。」
- 新增「正在启动守护，稍候会自动重试列目录…」（启动进行中时显示）。
