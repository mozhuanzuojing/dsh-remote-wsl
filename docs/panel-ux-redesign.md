## 1. 对 lead 八条现状批判的逐条核对（确认/部分确认/反驳 + 截图证据）

| # | lead 的批判 | 裁定 | 证据与理由 |
|---|---|---|---|
| 1 | **IA 混乱**：四类不同性质的东西平铺在一条纵轴；主任务不突出，无关运维细节占整块 | **确认（比描述更重）** | `ux-01`：纵轴上有 **5 段**（标题/目标、**浏览目录卡片**、**旧树**、原始 snapshot、底栏）。真正的病不是"东西多"，而是**两套目录概念并存**：「浏览目录」卡片在浏览 `/home/g/project/dsh1` 的内容，下面旧树又把**同一个 `dsh1` 目录**当成"收藏路径"再列一遍（同一屏出现两次同一路径，动作却在旧树上）。`ux-06`：多实例夹具下再加一块只读区块 ⇒ 与主任务无关的运维信息占据整段视觉高度 |
| 2 | **状态标签与交互混在一行** | **确认（仅旧树那一行）** | `ux-01` 旧树行整行是**一个** `<button>`，`aria-label`=「发行版 debian-u8-1（运行中，1 路径）」、`title`=「点击切换筛选并展开/折叠」；三个 chip（`默认发行版`/`运行中 · 1 路径`/`当前目标`）是**状态**，却与"点击进入/筛选"这个**交互**同处一行。对照：「浏览目录」卡片把导航（chips/面包屑/输入）与状态分开了 ⇒ 只要把旧树这一行重构掉，本条即解决 |
| 3 | **动作是裸文字且 hover 才显形** | **部分确认**（裸文字＝确认；hover 才显＝**反驳**） | 确认：`ux-01` 里 `在新会话中打开`/`复制路径` 是**右对齐纯文字**（无图标、无按钮边框/底色、无 affordance）。反驳：DOM census 显示两者**始终可见**（有 rect、在 a11y 树里、非 hover 门控）——"hover 才显形"对 `7cb3362` 不成立（那是我更早版本观察到的形态） |
| 4 | **实现者词汇直接给用户看** | **确认（分状态，程度不同）** | 就绪态主视线只剩 `daemon`；但：`ux-02` 加载态有 `explorer.snapshot（/remote-wsl/api，超时 9000ms）…`；`ux-09` 底栏 `daemon slot 8962 · :8962 · pid 1566872 · 0.2.0-rc.2 · keys 0`、动作 `重启…`/`停止 slot 8962…`、反馈句含 `systemd-run --user`/`unit`/`握手`；`ux-06` 只读区块 `slot 8731 · :8731 · pid …`/`非本槽位（configured daemonPort=8962）`；各态均可见 `原始 snapshot（与 wsl_status 同源）`。**对应我此前的 D5/D6** |
| 5 | **破坏性动作裸露在常显状态条** | **确认（守护运行态实测）** | `ux-09`：底栏把 `重启…` 与红色 `停止 slot 8962…` 与只读状态并排常显，**没有收进菜单**。守护未运行态只有非破坏性的 `启动守护`（`ux-01`）⇒ 问题只在"运行态"出现，但恰是最需要克制的时刻 |
| 6 | **缺一等入口**（无"添加工作区/选择目录"） | **部分确认** | 已有目录浏览器与**当前目录级**主行动 `在此目录开会话`（`ux-01`/`ux-03`）⇒ "无选择目录能力"不成立；但 ① **7cb3362 的面板上没有"添加为工作区"按钮**（工作区树里 i18n 已备 `action.addWorkspace*` 键，说明在路上）；② 没有**最近目录**；③ 没有任何按钮被提升为**头部一等行动** |
| 7 | **大面积空白**（内容约占上 1/3） | **确认但减弱** | `ux-01`：目录卡片把上半屏填满（10 行列表），但旧树 + 原始 snapshot 之后约 **250px** 仍空；且空白之上是**重复的同一路径**（见 #1）⇒ 空白的根因是结构冗余，不是内容不足 |
| 8 | **时间戳/刷新语义不明** | **确认** | `ux-01` 右下 `快照 09:21:53` 等宽小字：不说明"是自动刷新还是手动、多久过期、刷新会刷什么"。实测语义分裂：`刷新` 只重取 `explorer.snapshot`（含目录列表数据由 `listDir` 另取），底栏戳记只跟 snapshot；`ux-03` 证明目录导航**不会**更新戳记。另：D3（"不预热"只在 `title`）与 D4（"仅筛选不改目标"只在 `label.title`）在 `7cb3362` 上**仍在**（`header.distroFieldTitle`/`row.openTitle` 键名即证据） |

**结论**：8 条里 **6 条确认、2 条部分确认**（#3 的"hover 才显"与 #6 的"无选择能力"已被 `7cb3362` 部分解决），**0 条完全反驳**；但 #1/#7 的真实病根与 lead 的描述**不同**：不是"内容太少/太杂"，而是**两套目录概念 + 旧树残留**。

## 2. IA 与线框（骨架＝B：DSH 原生简洁；交互细节借 A）

### 2.1 三层结构（每块的目的与优先级）

```
┌ 面板：远程资源管理器 ─────────────────────────────────────────────┐
│ P0 头部                                                           │
│  [标题：远程资源管理器]         [主要动作：在此开会话 / 添加为工作区] [刷新] │
│  副标题：目标 <distro> · <cwd>            （视觉细节见 T28）        │
├───────────────────────────────────────────────────────────────────┤
│ P0 主体：目录浏览器（**唯一**的目录概念，取代旧树）                 │
│  行1 快捷 chips：Home · / · /mnt · /mnt/c…        [隐藏文件开关]    │
│  行2 面包屑：/ home / g / project / dsh1                           │
│  行3 常显路径输入：[/home/g/project/dsh1............] [跳转]        │
│  行4 条目列表（默认展开到当前目标目录；目录可键盘进入）              │
│        📁 vendor      → hover 出动作图标（见 §5）                   │
│        📄 README.md   → 惰性（无可执行动作，仅可"复制路径"）        │
├───────────────────────────────────────────────────────────────────┤
│ P1 折叠：详情（默认收起）                                          │
│  ▸ 最近目录（client 侧持久化，最多 8 条）                           │
│  ▸ 高级 / 诊断：原始 snapshot、其它实例的守护（只读）、版本信息      │
├───────────────────────────────────────────────────────────────────┤
│ P0 底栏：**一行**：● 自有守护状态 · 一句人话 · 最后刷新时间 · [⋯]    │
└───────────────────────────────────────────────────────────────────┘
```

**块级目的与优先级**

| 块 | 目的 | 优先级 | 必须/禁止 |
|---|---|---|---|
| 头部 | 说清"这是哪台机、哪个目录"，并把**一个**主行动放到拇指区 | P0 | 头部**只能有一个**主要按钮（`在此目录开会话` 或 `添加为工作区`，见 §5 裁决规则） |
| 目录浏览器 | 完成"选一个 WSL 目录"这件主任务 | P0 | **唯一**的目录概念；**必须**删掉旧树（`tree.*` 区域）与它的行内动作重复 |
| 折叠详情 | 把运维/诊断信息从主视线移走，但仍可查 | P1 | 默认收起；`others[]` **只在真有冲突时**以一行提示浮出（见 §4 多实例） |
| 底栏 | 一行说清"守护好不好 + 我什么时候看过" | P0 | 破坏性动作**不得**常显（进 `⋯`） |

### 2.2 结构级线框：底栏的三种形态（结构，不定视觉）

```
未运行： ● 远端守护未运行        [启动守护]                    最后刷新 09:21:53  [⋯]
运行中： ● 远端守护运行中 · 会话 0                                         最后刷新 09:21:53  [⋯]
异常：   ● 远端守护状态未知（读取失败）                                    最后刷新 09:21:53  [⋯]
```
`⋯` 菜单（结构）：`重启远端守护…` / `停止远端守护…` / `查看诊断信息` / `复制诊断摘要`。前两项**保留二次确认 + 后果文案**（§5）。

### 2.3 与旧结构的删除/迁移清单（实现时逐项打勾）

| 旧元素（`7cb3362` 实测） | 处置 | 理由 |
|---|---|---|
| 旧树 `▾ debian-u8-1 [默认发行版][运行中·1 路径][当前目标]` + `📁 dsh1` + `在新会话中打开/复制路径` | **删除**（信息并入头部副标题 + 面包屑 + 行内动作） | 与目录浏览器重复；且是 #1/#2 的病灶 |
| `WSL 目标 [下拉]`（当前只有 1 个选项） | **保留但降级**：仅当发行版 ≥2 时显示为下拉，否则显示为**只读文本** | D4：单选项＝死控件；"仅筛选不改目标"的语义须常显（§3 文案） |
| `原始 snapshot（与 wsl_status 同源）` | 移入 `▸ 高级 / 诊断`，摘要文案用户化 | #4；对账需求保留但降级 |
| `其它槽位的守护（只读…）` 大区块 | 移入 `▸ 高级 / 诊断`；**仅当真冲突**（同一 slot 上有非本实例的守护）时在底栏出一行提示 | #1；无冲突时它是纯噪声 |
| 底栏 `daemon slot … · pid … · keys …` | 换成一句人话 + `⋯` 菜单 | #4/#5 |
| `启动守护`（底栏右侧） | 保留（非破坏性、低频）但**并入底栏同一行** | 保持"一行状态" |
| 目录卡片内的 `在此目录开会话` | **提升为头部主行动**（若当前目录 ≠ 目标 cwd）；否则降为行内 | 让主路径在任何滚动位置都可见 |

## 3. 文案表（内部术语 → 用户语言；键名与 `client.i18n.js` 对齐）

### 3.1 术语映射（主视线必须用户化）

| 内部术语（现状原文） | 用户语言（zh-CN） | English | 键名 | 说明 |

### 5.1 主按钮裁决规则（消歧）

```
若 当前浏览目录 ≠ 目标 cwd        → 主按钮 = 「在此目录新建会话」
否则若 该目录尚未成为工作区        → 主按钮 = 「添加为工作区」
否则                              → 主按钮 = 「在本目录新建会话」（幂等，给出"已就绪"反馈）
```

### 5.2 破坏性动作的后果文案（沿用并用户化 M6 的既有结构）

```
确认停止远端守护？
这将关闭为「<distro>」启动的远端守护，正在运行的 <N> 个会话会全部中断、上下文丢失；
之后需要重新「启动守护」。
                                  [ 停止远端守护 ]  [ 取消 ]
```
- 必须包含三个要素：**影响对象**（哪台/哪个发行版）、**影响范围**（会话数 `{count}`）、**之后怎么办**。
- 若 `{count} = 0`：文案降级为「当前没有运行中的会话」，但**仍要确认**（保持一致性，不因"看起来无害"而跳过）。
- `重启` 的后果文案与 `停止` 的差异必须在首句可见（"会换一个新进程回来，且不会自动恢复会话"）。

### 5.3 行内动作的可发现性与命中区（可访问性硬约束）

- 行内动作**hover 才显形**是允许的（借 A 的成熟习惯），但必须满足：
  1. **命中区 ≥ 24×24px**，行高 ≥ 32px（触摸/精细度妥协值；视觉尺寸由 T28 定，**可点区域不得小于此**）；
  2. **键盘聚焦时同样显形**（`:focus-visible` 与 `:hover` 等价），且 tab 能到达；
  3. 图标必须有 `aria-label`（当前 census 证明本插件能做到 `titleOnly=0`）；
  4. 行本身若可点（进入目录），**行点击** 与 **行内动作点击** 必须分离（`stopPropagation`），避免误触发导航。
- 行内动作集合（仅目录行）：`在新会话中打开`/`添加为工作区`/`复制路径`；**文件行**只给 `复制路径`（文件不可执行动作，见 `browser.fileInertTitle` 的既有语义）。

### 5.4 窄宽度降级（**lead 2026-10-13 裁决**：`⋯` 全宽度只保留**一个**，在底栏）

| 宽度 | 头部 | 底栏 `⋯` 内 | 规则 |
|---|---|---|---|
| ≥720px | `主按钮(带字)` + `添加为工作区(带字, 次按钮)` + `刷新(icon)` | 守护组 / 诊断组 | — |
| 420–720px | `主按钮(带字)` + `添加为工作区(icon)` + `刷新(icon)` | 守护组 / 诊断组 | 次行动可降为图标 |
| <420px | `主按钮(带字)` + `刷新(icon)` | **工作区组**（`添加为工作区`）+ 守护组 / 诊断组 | **主按钮永不降级**；`添加为工作区` 是**次行动**，溢出进**底栏 `⋯` 的工作区组**（**不是**新开一个头部菜单） |

- **硬要求**（不因裁决变化）：① **主按钮在任何宽度都带字常显**；② `⋯` 在**所有宽度可达**（它是破坏性动作的唯一入口）；③ `⋯` 的 `aria-label` **唯一且稳定**（不随宽度/内容变化），菜单项文案与头部按钮**同键**（`action.addWorkspace`），避免"一个动作两个名字"。
- **为什么不是头部再开一个 `⋯`**：同屏两个同形 `⋯` 而内容不同 ⇒ 用户无法预测点开哪一组；底栏常驻 ⇒ 触发点位置稳定。（T28 提出、lead 采纳。）

### 5.5 明确**禁止**项（实现与复验都按此判红）

| # | 禁止 | 为什么 | 判红方式 |

## 6. 可达性与键盘

| 项 | 规格 | 验收（能红） |
|---|---|---|
| Tab 顺序 | 头部（主按钮 → 次按钮 → 刷新）→ 目录卡片（隐藏文件 → chips → 面包屑 → 路径输入 → 跳转）→ 列表（逐行）→ 折叠区（摘要）→ 底栏（状态 → `⋯`） | 逐次 `Tab` 记录的 `activeElement` 序列**单调前进**，且**不跳进**折叠区内部（收起时不可聚焦） |
| 焦点环 | 每个可聚焦元素必须有可见焦点环（对比度≥3:1）；**不得**用 `outline:none` 而不给替代 | 计算样式断言：`:focus-visible` 下 outline 非 `none`（T28 给视觉参数） |
| 行内动作 | `:focus-visible` 即显形（等价 hover） | 聚焦行时断言动作按钮 `visibility/opacity` 可见 |
| `aria-live` | **底栏状态** = `role="status" aria-live="polite"`；**错误/确认** = `role="alert"`/`alertdialog`（现状已有，**不回退**） | 状态变化时断言 live region 文本更新；`alertdialog` 存在 `aria-modal` |
| 图标可访问名 | rail 图标 + 行内图标都必须有可访问名；**装饰性 svg** 保持 `aria-hidden="true"` | census 断言 `unnamed = 0`（当前 31 控件已达标） |
| 键盘目录导航 | 列表支持 `↑/↓` 移动、`Enter` 进入目录、`Backspace` 回上级；面包屑可 `Tab` 逐段跳 | 键盘脚本断言：`Enter` 后面包屑末段变化（等价于 `ux-03` 的点击路径） |
| 确认弹层 | 打开后焦点移入弹层、`Esc` 取消、焦点回到触发按钮 | 断言 `Esc` 后弹层消失且 `activeElement` 回到 `⋯`/原按钮 |
| 折叠区 | 收起时内部元素 `tabindex=-1` 或 `hidden`，**不可被 Tab 到达** | `Tab` 序列不出现折叠区内部元素 |
| **状态句承载语义（终裁）** | 底栏「远端守护运行中/未运行/状态未知」**常显且永不省略**；颜色与形状只做**冗余**（T28：light `idle` 点仅 1.48:1） | **可判**：① 状态句节点存在且 `textContent.trim().length > 0`；② 该节点 `scrollWidth === clientWidth`（未被 ellipsis 吞掉）——**与 T28 §4.2 同一组 8 个宽度：`320 / 359 / 360 / 419 / 420 / 719 / 720 / 1280` 各测一次**；③ 状态点 `aria-hidden="true"`（语义只在文字里） |
| **层级不得靠底色（实测前提①）** | light 下 `bg-layer-1/-2/-3` **全为 `#ffffff`（1.00:1）** ⇒ 层级表达只能靠「背景档 + 描边 + 缩进/竖线」的组合，**不得**只靠"深一点的底" | 断言：在 light 下，任意两个**不同层级**的容器，其"可区分性"至少有一项来自描边/缩进/竖线（T28 §2.3 的三通道）；仅底色不同的两区在 light 下视为**未区分**（能红） |
| **边框不承担识别职责（实测前提②）** | 现有 token 中**没有**能达到 3:1 的描边（最重 `border-l4` 也仅 1.45）⇒ 控件识别靠「**文字标签 + hover 反馈 + 结构**」，描边只做视觉分隔 | 断言：任何**可交互**控件的可识别性不得只依赖 border（即：把 border 设为透明后，控件仍可由文字标签/图标/hover 反馈被识别） |
| **前提②的例外（记录，避免误伤）** | **焦点环不受前提②约束** —— 它由平台 `:focus-visible` 的 `outline` 绘制（实测 4.23:1 light / 6.75:1 dark），不是 border | 焦点环仍按上表"≥3:1 且不得 `outline:none`"判 |
| **"当前项"必须走形状通道（引用 T28 §5.1.1，不另立阈值）** | T28 三背景实测：hover/静息 = **1.11 light / 1.19–1.27 dark**（三处都非 1.00 ⇒ hover 可感知）；但**同一控件 hover→active 仅 1.08 light / 1.15–1.24 dark** ⇒ 用填充区分"按压/当前"在灰度与低视力下**不可辨** | **可判断言**：当前/选中行必须同时满足 —— ① 存在 `border-left: 2px solid var(--dsw-alias-brand-primary)`（或等效 2px 竖条元素，`getComputedStyle().borderLeftWidth === '2px'`）；② 该行 `font-weight >= 600`；③ **把填充色强制改成与静息态相同后，两态仍可区分**（即区分**不依赖**填充） |
| **菜单项（`menuitem`）文字必须单级 `label-primary`**（口径收窄，lead 2026-10-13 裁决） | 实测：`label-secondary` 在 `bg-overlay` 上 dark **3.85**（静息）、hover 底 dark 4.64 ⚠️、**active 底 light 4.10 / dark 2.81 ❌** ⇒ 这是**可点项**的对比度问题 | **可判断言**：菜单内**每一个 `[role="menuitem"]`** 的 `color` 解析值 === `--dsw-alias-label-primary`（两主题各测一次）；**禁止**两行"标题+副标题"结构（断言菜单项高度 ≤ 单行行高 + padding）。**注意：本断言不适用于组标题**（见下一行） |
| **组标题：必须实测两主题各 ≥4.5:1**（lead 2026-10-13 **改判**：3:1 → **4.5:1**） | 组标题虽非交互，但**是小字号正文文本** ⇒ 属 WCAG AA 文本门槛（4.5:1），不为分区标签留可访问性缺口 | **可判断言**：对每个组标题元素，用**计算样式**取其 `color` 与所在浮层（`bg-overlay`）的 `background-color`，按 WCAG 相对亮度算对比度，**两主题都必须 ≥4.5**；达不到就取能达标的 token（很可能就是 `label-primary`）。**能红形式**：注入样式把组标题色钉成低对比值（如 `--dsw-alias-label-dimmed` 或固定浅灰）⇒ 该断言必须红。<br>**层级感改由「非颜色线索」承担**：字号 11px / 不回 hover / 不可聚焦 / 无填充 —— **颜色不再承担层级**（与"状态 ≥2 种非颜色线索、禁止仅用颜色传达"一脉相承）。<br>**附加约束（保留，不是替代）**：组标题**不得**承载"不看就做不了事"的唯一信息（它只是分区标签） |
| **菜单分组标题的可访问性（引用 T28 新定稿）** | 三组各有**不可聚焦**组标题：`role="group"` + `aria-labelledby` 指向标题节点 | **可判断言**：菜单内存在 3 个 `role="group"` 且各有 `aria-labelledby`；组标题元素 `tabindex` 不为 0 且不出现在 `Tab` 序列里（键盘只在 `menuitem` 之间移动） |

#### 9.5.1 M16 收口依据（口径收窄，含实测数字与出处）

**裁决（含一次改判，如实记录）**：
- M16 的"菜单内所有文本 = `label-primary`"**只约束 `menuitem`**；
- **组标题**：允许弱样式，但**必须在菜单底（`bg-overlay`）上实测两主题各 ≥`T`**，达不到就取达标 token。
- **`T` 的取值经历了一次改判：3:1 → 4.5:1（2026-10-13，由本规格的下述实测把上限推上去的）**

**改判依据（"量具反过来修正裁决"）**：lead 最初裁 **3:1**，理由是"组标题非交互、不可聚焦，强对比会与层级冲突"；但我按 WCAG 口径指出**小字号非交互文字同样落在 AA 文本门槛 4.5:1**，而实测 dark = **3.85 < 4.5** ⇒ **该裁定会留下一个真实的对比度缺口**。lead 采纳并**改判为 4.5:1**，同时把"层级感"从颜色改由**非颜色线索**承担（11px / 不回 hover / 不可聚焦 / 无填充）。⇒ 记录这条，是因为**结论本身不如"结论是怎么被实测修正的"有价值**。

**依据一（T28 的视觉证据：`spike/verify/explorer-20261012/visual/out-03-contrast.txt` + `out-07-overlay-on-surfaces.txt`）**

| 菜单内文本 | 主题 | 静息（菜单底 `bg-overlay`） | 按 4.5:1 判 |
|---|---|---|---|
| **组标题** = `label-secondary` | light | **4.90** | ✅ 达标 |
| **组标题** = `label-secondary` | dark | **3.85** | ❌ **不达标**（这正是改判的触发点） |
| 启用 **`menuitem`** = `label-primary` | light / dark | **15.97 / 5.55** | ✅（M16 收窄后只约束它） |

**依据二（`client-panel` 的实现读数）**：实现里**组标题没有任何 `:hover`/填充规则**（`.dsh-rw-grouplabel` 不参与 hover）⇒ T28 实测中"active 填充底上 light **4.10** / dark **2.81**"的数字**对组标题不适用**（组标题只出现在静息底色上）。⇒ 判据只需在**静息菜单底**上取一次，且**不能拿 active 底的数字当理由**。

**可判形式（4.5:1 版）**：对每个组标题元素取 `getComputedStyle(el).color` 与其所在浮层的 `background-color`，按 WCAG 相对亮度算对比度，断言**两主题都 ≥4.5**；把组标题色钉成浅灰即红。**实现落点**：由 **T42** 把 `.dsh-rw-grouplabel` 的取色改到能满足 ≥4.5:1 的 token（很可能就是 `label-primary`）并给两主题实测读数。

**附加约束（保留，不是替代）**：组标题**不得**承载"不看就做不了事"的唯一信息（它只是分区标签）——这条与 4.5:1 同时成立。
