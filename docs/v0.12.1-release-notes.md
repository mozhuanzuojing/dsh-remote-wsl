# v0.12.1 发布说明（2026-11-25）

## 这一版在解决什么

**把"仓库 / 标签 / npm 包"三者对齐。** v0.12.0 的 npm 包是从工作区打出来的（含构建产物与门禁），
但那些文件当时还没进 git —— 于是 npm 上是完整的 0.12.0，GitHub 的 `v0.12.0` 标签却指向"没有构建产物"的提交。
0.12.1 就是把这份分发形态正式提交、打标签、重新发一版，从此 `v0.12.1` 标签 ↔ 提交 ↔ npm 包逐字一致。

**功能上 0.12.1 与 0.12.0 相同**（没有任何行为改动），差别只在分发包的形态与文档：

| 项 | 0.12.0 | 0.12.1 |
|---|---|---|
| 入口 | `main`/`exports` → `lib/*.js`（只在工作区） | 同左，**且已入库 + 随 tag 发布** |
| 构建 | `npm run build`（esbuild client + tsc host） | 同左；`build.ts.mjs` 更名为 `build.ts` |
| 门禁 | `check` / `check:contract` / `typecheck` / `test` | 新增 `check:pack`（tarball 逐个 entry 真加载） |
| npm | 已发 0.12.0 | 重发 0.12.1（`latest`） |

## 为什么需要构建产物（一句话背景）

Node 的类型擦除**拒绝 `node_modules` 里的 `.ts`**（`ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING`）。
`link:` 装的是工作树、能直接跑 `src/*.ts`；从 npm 装文件落进 `node_modules/`，宿主半与 WSL 侧守护半
都会拒绝加载 —— 所以 `main`/`exports`/守护脚本一律指向 `npm run build` 产出的 `lib/*.js`。

## 开发循环的变化

`main` 指向 `lib/` 之后，改 `src/` 必须重建宿主才会用上新代码：

```powershell
npm run build     # 一次性
npm run dev       # 或挂着 watcher（tsc -p tsconfig.build.json --watch）
```

## 验证

`check`（60 TS）/ `check:contract`（12 条）/ `tsc -p tsconfig.json` / `check:pack`（11 条，真 tarball 加载）
/ `node --test`（351 tests，338 pass，0 fail，13 skipped）全绿；公开 registry 装 `0.12.1` 后
`main` 与四个子路径均可 import，`lib/daemon.js` 可启动。
