## 3. 关键机制

- **数据面**：`src/explorer.ts` 方法表 **7 个**（`snapshot / openSession / daemon / fixPin / listDir / addWorkspace / newSession`），`POST /remote-wsl/api`；传输层闸门见上表第一行。
- **客户端**：`client/*.js` 零构建 chunk；入口 `client/index.js` 的 rev 取自入口元数据，**改任何 chunk 都要动入口**（`check-client-rev` 门禁）。
- **面板结构**：`client.panel.js`（接线/状态）、`.header.js`（头+主按钮+结果条）、`.tail.js`（底栏/折叠/菜单/确认）、`.browser.js`（WSL 目标/会话卡/目录卡）、`.list.js`（行/键盘/虚拟化）、`.actions.js`（hook）、`.data.js`（目录缓存）、`.helpers.js`。
- **目标切换**：`api.setDistro` 把 distro 合并进每次请求；host 用 `listDistros()` 校验，未知 ⇒ E_ARG，WSL1 ⇒ E_ARG。
- **新会话**：`addWorkspace({path})`（UNC）→ 客户端 `ctx.get("uiWorkspace").startSession(workspaceId)`（与侧栏「新会话」同一路径，会切主视图）；客户端没有该服务时回落 `explorer.newSession`。
- **守护**：按需启动；无 keys 且无客户端 10 分钟自退（`daemonLingerMs=600000`）；运行时 idle 30 分钟回收（`daemonIdleMs=1800000`）。版本来自元数据，display 在药丸 title 与诊断行。
- **最近目录**：localStorage `dsh-remote-wsl.recent` 存 `{[distro]: string[]}`；旧数组读成 `"*"` 并在读取时回退。

## 5. 未验证 / 已知风险

1. **`uiWorkspace.startSession` 只做了单元探针，没有真机验证**：插件 client 上下文是否能 `ctx.get("uiWorkspace")` 未验证；若拿不到，会静默回落到 host `newSession`，用户仍会看到「已创建 DSH 会话」但主视图不切（即用户报的"没反应"）。
2. host `newSession` 建的是 blank 会话；客户端列表/主视图不会自动跟随（回落路径的固有行为）。
3. **异步化未做**：`wsl -l -v` / `wsl -l -q` 仍是 `spawnSync`（已加 8s 超时），`daemonSnapshot` 整条链同步；WSL 冷启动时可能卡住 host。
4. 窄态（<420px）未回归；行内动作没有右键菜单。
5. 只显示本插件槽位的守护；别的槽位只读（`others[]`）。
6. 未实现 VS Code 的 Delete Distro（`--unregister`）、Add Distro、New Window。
7. WSL1 只在解析层拒绝，没有真实 WSL1 机器验证。

## 6. 下一步建议（按优先级）

1. **真机确认新会话路径**：刷新页面点一次，看主视图是否切换、控制台有无 `ctx.get` 报错；若拿不到 `uiWorkspace`，改在 `package.json` 的 `dsh.client.inject` 里声明它，或改用客户端命令系统。
