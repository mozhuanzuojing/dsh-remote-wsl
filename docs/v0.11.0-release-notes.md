## 亮点

面板「远程资源管理器」自愈：**目标探测失败自动重探** + **远端守护未运行自动启动**，减少“面板一片红、还要手工去调 `wsl_status` / `wsl_daemon`”的运维步骤。

## 新增

### 目标探测自愈（A+B）
- 新增后端方法 `explorer.redetect`（`POST /remote-wsl/api`）：复用 `refreshAutoTarget()` 清进程缓存重探 `distro`/`wslHome`/`cwd`，**原地更新运行中配置**；返回 `{ok, problem, notes, previous, current, changed, auto, target}`，探不到目标时 `ok:false`（不抛）。
- 面板在 snapshot 因 `no-distro` / `no-wsl-home` 失败时**自动重探一次**并重载（15s 冷却 + 模块级节流，防循环）。
- 错误卡片新增「重新探测目标」按钮（手动触发，带 in-flight 防抖）。
- client 为 `explorer.redetect` 设 **30s 独立预算**（覆盖最坏 8s+10s 探测，避免被读动作 9s 超时误判）。

### 远端守护自动启动（C）
- 面板读到守护**已知未运行**时自动 `explorer.daemon{action:"ensure"}` 一次，成功后刷新快照。
- 防误触：每段“未运行”只自动一次（运行恢复后重置）；**按发行版分键**；扫描未核实不拉；有其它动作在跑不抢占；**用户手动停止后本会话不再自动拉起**。

### 其它
- client 抽出 `isTargetResolutionError` / `shouldAutoStartDaemon` / `hostReason` 共用判定；i18n 中英成对新增文案。
- 文档方法表 9 → 10 同步（`explorer.redetect`）。

## 兼容性 / 行为变化
- **显式配置**（`distro` + `wslHome` 都写死）时 `redetect` **不探测**（`auto:false`）、值不变；自愈只对“自动探测型”机器生效。
- 无需数据迁移；旧守护 / 旧协议不受影响。

## 已知限制
- `explorer.redetect` 依赖同步 `spawnSync` 探测，最坏会**阻塞 host 事件循环约 18s**（已用冷却 + 节流限频；彻底异步化列为后续项）。
- 自动启动守护在“打开面板且守护未运行”时触发，冷启动约 22s 并常驻占资源；用户手动停止后本会话不再自动拉起。

## 升级指引
1. 更新到 v0.11.0 后**重启 DSH Desktop**（host 插件与 client bundle 均在启动时加载）。
2. 可选：在 profile `cordis.patch.yml` 显式写 `distro` / `wslHome`，可完全跳过启动探测，彻底规避冷启动探测超时。
