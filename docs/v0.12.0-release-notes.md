# v0.12.0 发布说明（2026-11-24）

## 一句话

修掉"WSL 插件有时候报错、`wsl_daemon status` 却正常"的那条根因：**连接 churn 打光 Windows 临时端口池**；
顺带把"整树搜索"接进标准 preset 会话（世界路由），并给不能改世界的会话一个确定性逃生口。

## 面向用户

- **不再出现 `connect EADDRINUSE 127.0.0.1:8731`**：`fs`/`search`/`status` 改成长连接复用 + 只读批量帧，
  连接数从"每 op 一条"降到"一条"；同样的 300 次 `fs.stat`，隔离守护实测 300 条/622ms → **1 条/127ms**
  （池化+批量 **1 条/14ms**）。
- **WSL 工作区的新会话自动落进 WSL 执行世界**（`worldRoute`，默认开）：`grep`/`glob` 变成守护里的一次
  `{op:'search'}`（扫完整棵树，不走 9P）。`resume`/用户显式选过的 preset 一律不动；`worldRoute: false` 可关。
- **新工具 `wsl_grep` / `wsl_glob`**：路径在 WSL 里时用它代替 `grep`/`glob`（标准 preset 会话的逃生口）。
- 报错文案变准：EADDRINUSE 现在直接说"Windows 临时端口不够用，等 1–2 分钟 / 减少大范围扫描"，
  不再往"WSL 内存/swap"上引。

## 面向维护者

- 协议 **v5**：`fs` 新增 `batch`（上限 64，逐条独立成败）；宿主侧长连接池按 `id` 配对、空闲 45s 关、
  超时即断。旧守护 ⇒ 池化仍可用、`batch` 自动降级（`batchUnsupported`）。旧宿主 + 新守护 ⇒ hard 拒绝并
  提示重启（协议版本保护，非故障）。
- 诊断开关：`DSH_RWSL_FS_POOL=0`（退回短连接）、`DSH_RWSL_FS_BATCH=0`（只池化不批量）、
  `DSH_RWSL_POOL_IDLE_MS`（池空闲关闭）。
- 明细与实测数据：[docs/2026-11-24-connection-churn-v5.md](2026-11-24-connection-churn-v5.md)。

**重启 DSH Desktop**（host 半代码在启动时加载）。守护侧代码每次启动读源码，已自动是新版。
